## 반드시 고칠 것 (사실 오류)

### 15 · PG ts_rank

| 틀린 문장 | 고칠 문장 |
|---|---|
| ts_rank=Σ(가중치×단어 빈도) saturation이 없어 등장 횟수에 선형적으로 반응 | ts_rank는 같은 단어가 j번째 나올 때마다 가중치/(j+1)²를 더하고 π²/6 으로 나눈다 → 반복될수록 기여가 줄어드는 포화 구조. AND 질의에서는 단어 간 거리도 반영 |

근거 : 같은 단어를 1·2·3·10번 반복한 문서의 ts_rank = 0.061 → 0.076 → 0.083 → 0.094 로 수렴 (`notebooks/03_ts_rank` 셀 4)

```c
/* tsrank.c calc_rank_or */
resj = resj + wpos(post[j]) / ((j + 1) * (j + 1));
res  = res + (wjm + resj - wjm / ((jm + 1) * (jm + 1))) / 1.64493406685;   /* π²/6 */
```

### 16 · PG ts_rank_cd

| 틀린 문장 | 고칠 문장 |
|---|---|
| 분문:A..B..C..A..B | 본문:A..B..C..A..B |
| 전체 구간으로 볼 때:등장토큰(ABC)/길이=3/13=0.23 / A..B..C / A..B 두 구간으로 볼 때:3(ABC)/7 + 2(AB)/4=0.92(고득점) | 질의어를 모두 포함하는 최소 구간(커버)을 문서 앞에서부터 차례로 모두 찾는다. 커버 점수 = 커버 안 질의어의 평균 가중치 ÷ (1 + 커버 안 잡음 단어 수), 문서 점수 = 커버 점수의 합 |
| 분할조합 중 가장 고득점이 되게 나눔 | 최적 분할을 찾지 않는다. 최소 커버를 순서대로 모두 세며 커버끼리 겹칠 수도 있다 |
| sum(구간내토큰가중치합/구간길이) … ts_rank_cd =(1.2+0.5)/4 + (1.2+0.5+0.8)/5 | Σ 커버 평균가중치 / (1 + 잡음 단어 수) — 예: 붙어 있는 두 단어(D 가중치 0.1) = 0.1, 사이에 8단어 = 0.1/9 = 0.011 |
| ts_rank가 등장횟수에 선형적인 특성을 밀집도로 보강함 | ts_rank 가 보지 않는 '질의어끼리의 거리'를 반영한다. 오히려 cd 는 커버 수에 선형(같은 단어 n번 → n배)이다. OR 질의에서는 단어 하나로 커버가 되므로 거리 효과가 사라진다 |
| (번호) 마지막 "4." | "6." (4가 두 번 나옴) |

근거 (`notebooks/03_ts_rank` 셀 5)

| 문서 | AND ts_rank_cd | 1/(1+잡음) × 0.1 |
|---|---|---|
| 붙어 있음 | 0.1 | 0.1 |
| 사이에 8단어 | 0.0111 | 0.0111 |
| 사이에 30단어 | 0.0032 | 0.0032 |

커버가 여러 번 나오면 합산된다 : 1개 0.1 · 2개 0.225 · 3개 0.4

### 20 · BM25 토큰 수와 커버리지

| 틀린 문장 | 고칠 문장 |
|---|---|
| 토큰 1개:BM25=IDF×TF 한 번 TF는 어차피 포화되므로 IDF(희귀성)의 영향력이 큼. 그 단어가 얼마나 희귀한가가 점수를 지배 | 토큰 1개:IDF 는 모든 문서에 같은 상수라 순위에 영향이 없다. 순위는 TF(포화)와 길이 보간만으로 정해진다 |
| 토큰 20개:IDF 영향력이 거의 소실되고 커버리지의 영향력이 커짐 | 토큰이 많을수록 IDF 의 영향은 줄지만 9개 이상에서도 남는다(아래 표). "거의 소실"은 과장 |
| 임베딩 검색은 보통 문장으로 들어와 토큰 수가 충분히 많은 편임 TF-IDF가 아니라 TF만 써도 충분하고, 오히려 부족한 IDF는 임베딩이 보완 | 문장 질의(형태소 7개 이상)에서는 IDF 를 꺼도 MRR 손실이 약 0.06 으로 작아진다. 단 0 은 아니므로 "TF 만으로 충분"은 조건부 — 짧은 질의일수록 IDF 가 필요하다 |

근거 : 같은 질문 500개를 BM25 로 검색하되 IDF 를 켠 것과 끈 것(모든 단어 IDF = 1)의 MRR 을 질의 형태소 수별로 비교 (`notebooks/04_BM25` 셀 9)

| 질의 형태소 수 | 질문 수 | MRR IDF 켬 | MRR IDF 끔 | 차이 |
|---|---|---|---|---|
| 4 이하 | 27 | 0.755 | 0.467 | 0.288 |
| 5~6 | 138 | 0.790 | 0.618 | 0.172 |
| 7~8 | 168 | 0.832 | 0.770 | 0.063 |
| 9 이상 | 167 | 0.895 | 0.834 | 0.061 |

> 정정 기록 : 이 항목의 이전 판은 "흔한 형태소가 많이 섞일수록 IDF 의 역할이 커진다"로 슬라이드와 반대 방향을 주장했다.
> 근거로 쓴 비교(IDF 없는 ts_rank 0.484 vs BM25 0.938)는 IDF 외에 순위 함수 자체가 달라 IDF 의 효과만 떼어 보지 못했다.
> IDF 만 켜고 끈 위 측정은 슬라이드의 방향(토큰이 많을수록 IDF 영향 감소)을 지지하고, 크기("거의 소실")는 지지하지 않는다.

### (슬라이드 번호 확인 필요) · pgvector 의 형태소 분석 · 동의어 · 불용어

| 틀린 문장 (강사 전달 요지) | 고칠 문장 |
|---|---|
| pgvector 의 형태소 분석기도 동의어나 스탑워드를 지원 | 한국어 형태소 분석 · 동의어 · 불용어는 pgvector 기능 아님. PostgreSQL 전문검색에 사전을 끼우는 틀(사전 템플릿)만 내장 — 한국어 불용어 · 동의어 목록은 없어 직접 파일로 만들어 DB 서버에 넣어야 함. 한국어 형태소 분석(textsearch_ko)도 내장이 아닌 외부 확장. 파일 없이 되는 것은 질의 다시 쓰기(ts_rewrite)뿐 |

근거 (`notebooks/07_동의어_불용어`, 질문 500개)

- 내장 여부 (컨테이너에서 확인) : PostgreSQL 이 주는 불용어 파일은 영어 · 독일어 등 15개 언어뿐이고 한국어는 없다. 동의어 파일은 예제(`synonym_sample.syn`)뿐. textsearch_ko 는 배포판 패키지가 아니라 GitHub 소스를 빌드해 넣은 것이고, 그 사전(`mecabko` 템플릿)은 옵션을 받지 않아 불용어 · 동의어 파일을 붙일 수 없다
- 관리형 DB(RDS 등)는 서버 폴더에 파일을 넣을 수 없어 사전 파일 방식은 보통 불가 (제공사별 미검증)
- 한국어 조사 · 어미 · 접속부사는 textsearch_ko 파서가 품사로 이미 버린다(셀 3). 이 규칙은 코드에 고정되어 조정할 수 없다
- 실습에서는 불용어 · 동의어 파일(`db/tsearch/korean_lab.*`)을 **직접 만들어 DB 이미지에 넣고**, 불용어 사전(simple) · 동의어 사전(synonym)을 mecab 사전 앞에 끼워 문서 · 질의 양쪽에 적용했다(셀 7). 사전은 mecab 이 자른 **형태소**를 받는다(`전기자동차` 규칙은 안 먹음)
- 파일 없이 질의만 바꾸는 `ts_rewrite` 도 있다(셀 6, "스마트폰 판매" 69 → 86건)
- 효과 : 질의 불용어(문서 빈도 상위 100) ts_rank Hit@10 0.484 → 0.540 · BM25 0.938 → 0.930 (IDF 가 이미 누름, 셀 5)

### 23 · PreFilter / PostFilter / AllowList

| 틀린 문장 | 고칠 문장 |
|---|---|
| HNSW·IVF 인덱스는 전체 데이터에 대해 단 1개만 생성 -사전 필터를 했다 해도 그 인덱스 자체는 변하지 않으므로, "줄어든 부분집합만의 그래프"를 따로 탐색하는 것은 논리적으로 불가능 | 기본은 테이블당 인덱스 하나라 필터 조건에 맞는 부분집합만 따로 탐색하기 어렵다. 부분 인덱스(CREATE INDEX … WHERE)나 파티셔닝으로 부분집합 인덱스를 따로 만들 수 있고, pgvector 0.8 의 iterative index scan 이나 Qdrant 의 filterable HNSW 처럼 필터를 탐색에 결합하는 기법도 있다 |

보충 : pgvector 에서 `WHERE` + `ORDER BY <=>` 를 HNSW 로 실행하면 실제로는 PostFilter 처럼 동작한다 (기본 ef_search 40개를 뽑은 뒤 거름). 이 한 줄을 추가하면 Pre/Post 차이를 설명하기 좋다.

## 실습 장표와 맞출 곳

실습 장표(Google Slides)는 아래 두 슬라이드에서 원본 강의 슬라이드의 설명이 틀렸다고 직접 짚는다.
원본을 고친 뒤에는 이 문구도 "강의에서 본 대로"로 바꾼다.

- 「반복 실험 : ts_rank 는 포화」 — "강의 슬라이드의 'saturation 이 없어 선형' 과 다르다"
- 「k1 : TF 포화 곡선」 — "강의 슬라이드의 '클수록 TF 억제' 는 반대"
