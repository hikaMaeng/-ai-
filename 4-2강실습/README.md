## ② 1부 — 인덱스 원리를 numpy 로 (10 ~ 13)

| 노트북 | 직접 만드는 것 | 핵심 관찰 |
|---|---|---|
| 10 NSW | 점을 하나씩 넣으며 가까운 M개와 친구 맺기 → 그리디 탐색 | 그리디만으로는 최근접을 35% 만 맞힌다(지역 최적). 후보 폭 ef=16 이면 99%. M=2 면 그래프가 끊겨 **섬**이 생긴다 |
| 11 HNSW | 논문 알고리즘 100줄 구현: 층 배정 · 층별 탐색 · 이웃 선택 휴리스틱 | 100만 노드의 층별 개수가 N·M^(−층) 과 일치. 1만6천 개에서 위층부터 내려오면 recall 0.99, 0층부터면 0.81. **다양성 휴리스틱 0.99 vs 단순 최근접 M개 0.72** |
| 12 IVF | k-means(무작위 vs k-means++) → 역색인 → nprobe 검색 | 보로노이 경계 너머의 정답을 nprobe=1 은 놓치고 2 는 찾는다. nlist≈√N 곡선이 가장 효율적. 학습 시간 ∝ N·k·d·T. 10% 표본으로 학습해도 recall 0.84 → 0.83 |
| 13 PQ | 64차원 → 8조각 × 256 코드북 → 8바이트, LUT 로 거리 계산 | 표 조회 합 = 복원 벡터와의 거리(정확히 일치). PQ 만 recall 0.31 → 후보 500개 재정렬 1.00. 잔차 PQ 가 오차 29.6 → 18.8 |

## ③ 2부 — pgvector 로 측정 (20 ~ 24)

20번이 합성 벡터 두 벌을 만든다: **군집형**(중심 200개 + 잡음) · **무구조형**(등방 가우시안), 각 10만 × 128차원, 질의 200개와 정확한 정답지(top-100).

| 노트북 | 핵심 관찰 |
|---|---|
| 20 데이터 | 최근접까지의 거리 / 평균 거리 = 군집형 0.59 · 무구조형 0.77 (고차원 거리 집중) |
| 21 HNSW | 빌드 5초 · 인덱스 79MB(테이블 56MB 보다 큼). ef_search=40 에서 **군집형 0.92 · 무구조형 0.41**. `<=>` 질의는 L2 인덱스를 못 탄다. **LIMIT 100 인데 ef_search=40 이면 40행만 온다**. m=4 는 recall 0.28 |
| 22 IVFFlat | probes=1(기본값) 0.86. **군집형에서는 IVFFlat(lists=316, probes=4)이 recall 1.0 으로 HNSW 보다 낫고, 무구조형에서는 probes=64 에도 0.67 로 무너진다**. 절반의 분포로 만든 인덱스에 새 군집이 들어오면 recall 0.49 → REINDEX 후 1.0 |
| 23 양자화 | halfvec 인덱스 54MB(−31%) recall 0.981 ≈ float32 0.985. 1비트 인덱스 30MB 는 단독 0.15 → **후보 400개를 원본으로 재정렬하면 0.975** |
| 24 필터 | 1% 필터 + HNSW 는 LIMIT 10 에 평균 0.4행(PostFilter 함정). 플래너는 B-tree 가 있어도 HNSW 를 고른다 → PreFilter 는 `MATERIALIZED` CTE 로 직접. `hnsw.iterative_scan` 으로 1% 필터도 10행. **선택도에 따라 PreFilter 와 iterative 의 지연시간이 교차**. 부분 인덱스(`WHERE tag = 7`)는 recall 1.0 |

> 지연시간은 1ms 안팎이라 네트워크 왕복·잡음이 섞인다. recall 은 재현되지만 ms 는 경향만 본다.

## ④ 3부 — 검색 품질 (30 ~ 31, KLUE-MRC 질문 500개)

| 방법 | Hit@10 | MRR |
|---|---|---|
| BM25 (4-1 직접 구현) | 0.938 | 0.838 |
| 벡터: 지문 통째 (4-1 과 같음) | 0.386 | 0.208 |
| 벡터: **250자 청크** (4-2 추가) | 0.500 | 0.317 |
| RRF k=60 | 0.900 | 0.639 |
| RRF k=1 | 0.940 | 0.796 |
| **Min-Max α=0.7** | **0.954** | **0.844** |

| 노트북 | 핵심 관찰 |
|---|---|
| 30 퓨전 | BM25 는 5~72, 코사인은 0.45~0.96 → 그냥 더하면 안 된다. RRF 곡선에는 **변곡점이 없고** k 는 쏠림 정도만 정한다. 흔한 k=60 은 약한 벡터와 동등하게 섞어 MRR 을 깎는다. Min-Max 의 약점: 1위가 압도적이면 나머지가 0 근처로 눌린다 |
| 31 분포 진단 | 맞힌 질문은 1위가 튀어나온 곡선, 틀린 질문은 밋밋한 곡선. 2차 차분 · 최대 간격 · Kneedle 무릎점 비교. **분리도 상위 20% 만 답하면 벡터 1위 정확도 0.25 → 0.7**. 관련 없는 쌍의 코사인도 평균 0.15(이방성). 맞는 분야 필터 Hit 0.45 → 0.71, 틀린 필터는 1위 유사도부터 급락. 벡터 검색의 허브 지문(한 지문이 21개 질문의 top-10) |

## 강의 슬라이드와 비교해 볼 결과

> 슬라이드 번호별 원문 → 고칠 문장은 [강의슬라이드_수정사항.md](강의슬라이드_수정사항.md)

| 슬라이드 | 실습 결과 |
|---|---|
| "같은 속도에서 recall 은 HNSW 가 최고" | 데이터에 따라 다르다. 군집이 뚜렷하면 IVFFlat 이 낫고(22번), 무구조면 HNSW 가 낫다 |
| "범주가 뚜렷하면 IVF" | 맞다. 반대로 범주가 없으면 IVF 는 특히 크게 무너진다 |
| HNSW 이웃 선택 "가장 가까운 M개" | 실제는 다양성 휴리스틱. 군집 데이터에서 차이가 크다(11번 0.99 vs 0.72) |
| "HNSW 는 metric-agnostic" | 알고리즘은 그렇지만 **만든 인덱스는 척도 하나에 묶인다**(21번) |
| PQ "512차원을 8차원 압축" | 8차원 벡터가 아니라 **8바이트 코드**다(13번) |
| RRF "k 로 변곡점 조절" | 1/(k+rank) 에는 변곡점이 없다. k 는 쏠림 정도(30번) |
| "2차 미분으로 변곡점" | 이산 점수에서는 잡음에 민감. 최대 간격·Kneedle 도 함께 본다(31번) |
| "PreFilter 는 인덱스가 하나라 부분집합 그래프 불가" | PG 는 부분 인덱스로 가능하다(24번) |
