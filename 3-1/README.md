# 3강 실습 — 벡터 연산을 실제 산업 데이터로

> 현대 AI의 원리와 구조 #3 임베딩 · 벡터 연산(장표 17~23) 실습 · 뉴런데브클래스
> 준비물 : [4-1](../4-1/) 의 도커 환경(`docker compose up -d --build`, pgvector DB · Jupyter)과 **LM Studio**(Qwen3-Embedding-8B, 서버 켬). 실습 화면은 같은 Jupyter(http://localhost:8888) → `3-1/notebooks`

장표의 벡터 연산(평균 · 가감 · 프로토타입 분류 · Rocchio)을 공식이 아니라 **실제 서비스가 하는 일**로 증명한다.
허깅페이스의 공개 데이터를 4-1 과 같은 **PostgreSQL + pgvector** 테이블에 넣고 Qwen3-Embedding-8B 로 임베딩한 뒤,
쇼핑몰 추천 · 산업재해 분류 · 판례 검색 등을 **SQL 한 문장(앱)** 과 **대량 채점(행렬 연산)** 으로 돌려 "이 연산이 얼마나 도움이 되는가"를 기준선과 비교해 잰다.

```
3-1/
├─ README.md
└─ notebooks/                   코드 셀 첫 줄 = "# 셀 N · 제목", 설정은 셀 1
   ├─ 01_중심벡터_추천.ipynb       장표 18 · 20 : 구매 이력 평균 = 취향 벡터로 다음 구매 맞히기 · 추천 SQL · HNSW 추천 API
   ├─ 02_속성가감.ipynb           장표 19 : "스위치판 + (PS4 방향)" → 같은 게임의 PS4판 · 가감 SQL · 임베딩 쏠림
   ├─ 03_프로토타입_분류.ipynb     장표 21 : 9개 산업에서 예시 몇 개로 분류 · 분류 API · 코사인 vs 내적 · "기타" 거르기
   └─ 04_Rocchio_질의확장.ipynb    장표 22 · 23 : 유사 사례 검색에서 실제 피드백(관련 표시) vs 의사 피드백 · 쿼리 드리프트 · KLUE-MRC
```

## 실습마다 따로 돈다

노트북 하나가 **받기 → 테이블 만들기 → 적재 → 임베딩 → 실습** 을 다 한다. 순서와 상관없이 어느 것부터 해도 된다.
수업 중에 기다릴 수 있게 기본 표본을 작게 잡았다(셀 1 에서 키울 수 있다).

| 노트북 | 테이블 (스키마 `lab3`) | 기본 표본 | 임베딩 행 | 실행 시간 (강사 PC 단독 · 캐시 비움) |
|---|---|---|---|---|
| 01 | `shop_items` · `shop_purchases` | 사용자 500명이 산 상품 | 3,261 | 20분 (임베딩 초당 2.7건) |
| 02 | `game_items` | 여러 플랫폼판이 있는 게임 256개(587판) + 플랫폼마다 다른 게임 300 | 2,065 (01 뒤면 259건은 캐시) | 13분 |
| 03 | `cls_items` · 뷰 `cls_proto` | 9개 데이터셋 × 클래스당 예시 후보 10 · 시험 20 | 4,317 | 21분 |
| 04 | `case_items` | 4개 과제 × 약 550 (질의 100) | 2,180 (03 뒤면 1,013건은 캐시) | 8분 |

- 실행 시간은 LM Studio(Qwen3-Embedding-8B, 강사 PC)를 이 노트북만 쓸 때 01 → 02 → 03 → 04 순서로 잰 값. 임베딩 속도는 글 길이와 PC 에 따라 크게 다르다(짧은 명령 · 제목은 빠르고 판례 · 특허는 느림)

- 셀 1 · 2 는 네 노트북이 같다(DB · LM Studio 주소, 내려받기 · 임베딩 도구). 공통 모듈 없이 노트북마다 들어 있다
- 테이블은 4-1 의 `docs` 와 같은 규칙 : `embedding vector(4096)`(원본) · 01 은 `emb128`(앞 128차원을 다시 길이 1로, HNSW 는 여기에)도 둔다
- 벡터 연산은 pgvector 연산자로 : 평균 `avg(embedding)` · 가감 `+` `-` · 코사인 거리 `<=>` · 음의 내적 `<#>` · 길이 `vector_norm()`
- 4-1 의 테이블은 건드리지 않는다

### 임베딩 캐시 `lab3.emb_cache`

| 항목 | 내용 |
|---|---|
| 키 | (모델 이름, `md5(글)`) → `vector(4096)` |
| 쓰는 곳 | 각 노트북 셀 6 `embed_table()` : 빈 행을 먼저 캐시에서 채우고, 남은 행만 LM Studio 로 계산해 캐시에도 넣는다 |
| 효과 | 같은 글은 한 번만 계산 — 01 · 02(같은 쇼핑몰 상품), 03 · 04(판례 · 사고 · 결함 신고)가 겹치는 글을 다시 계산하지 않는다. 셀 1 `RESET = True` 로 테이블을 다시 만들어도 벡터는 캐시에서 돌아온다 |
| 크기 | 계산한 서로 다른 글 수만큼 (한 행 약 16KB) |
| 지우기 | `TRUNCATE lab3.emb_cache` (실습 테이블과 따로. `docker compose down -v` 는 DB 전체를 지운다) |

- 표본은 라벨마다 같은 시드로 뽑는다 → 작은 표본은 큰 표본의 앞부분. 표본을 키우면 이미 계산한 글은 캐시에서 채워지고 늘어난 만큼만 계산한다

## 실증 결과 (수업 크기 · 2026-09-29)

기본 표본으로 01~04 를 실행한 결과. 괄호는 부트스트랩 95% 신뢰구간(✔ = 0 을 포함하지 않음). 판정 기준과 전체 규모 결과는 로컬 `tests/plans` · `tests/reports` 에 있다.

| 실습 | 연산 | 결과 |
|---|---|---|
| 01 | 이력 평균(취향 벡터)으로 다음 구매 맞히기 | 원래 벡터의 평균은 약하다(Hit@10 0.048, 마지막 구매 0.076). 상품 벡터끼리 코사인 평균이 0.48 로 쏠려 있어 평균이 공통 방향을 가리킨다 → **공통 성분(상품 전체 평균)을 빼고 평균하면 0.090**(+0.042 ✔), 최근 가중 · 공통 성분 제거 0.100 |
| 01 | 시간 순서를 뺀 채점(무작위 하나를 가림) | 공통 성분을 뺀 평균 0.088 > 공통 성분을 뺀 이력 중 한 개 0.060 (+0.028 ✔) > 인기순 0.034 — 여러 구매의 평균이 취향을 대표 |
| 01 | HNSW 후보 → 원본 재정렬 | 후보 200 에서 전수와 같은 Hit@10, 한 건 34.4ms → 5.1ms |
| 02 | 가감 `원래 상품 + (B 평균 − A 평균)` | 같은 게임의 다른 플랫폼판 1위 성공 0.560 → 0.775 (+0.178 ✔, 게임 256개 단위). 메타데이터 필터는 0.855 |
| 03 | 예시 3개 평균 = 프로토타입 | 9개 산업 모두 찍기보다 높고(✔), 예시 1 → 10 개로 좋아지고(✔), 7개 산업에서 코사인 > 내적(✔) |
| 04 | 실제 피드백 `q + β·mean(관련) − γ·mean(무관)` | 11위 이후 P@10 : lbox +0.073 · osha +0.160 · nhtsa +0.123 · aviation +0.157 (모두 ✔) |
| 04 | 의사 피드백 `q + β·mean(상위 k)` | +0.018 ~ +0.048 (osha · nhtsa 만 ✔). 1차가 빗나간 질의에서는 오히려 떨어짐. KLUE-MRC(정답 지문 1개)에서는 Hit@10 · MRR 이 떨어짐 |

- 04 채점은 **잔여 집합** : 사용자가 이미 본 1차 상위 10건은 빼고 11위 이후에서 P@10. 관련 표시는 라벨(죄명 · 사고 유형 …)로 흉내 낸다
- 전체 규모(사용자 9만여 명 중 5,000명 채점 · 후보 상품 25,612개)에서도 결론이 같다 : 공통 성분을 뺀 평균 0.0126 → 0.0244 ✔, 무작위 하나를 가린 채점에서 평균(제거) − 한 개 +0.015 ✔. 다만 원래 벡터의 평균은 전체 규모에서 인기순(0.0228)보다도 낮다 — 수업 크기의 인기순은 500명 이력으로만 세어 약하다
